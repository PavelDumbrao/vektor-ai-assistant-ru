# Что-то не работает: симптом → причина → лечение

Все случаи из реальной практики. Ищите свой симптом. Чинить руками не обязательно — можно просто показать эту страницу своему агенту.

## Установка

**Сервис падает по кругу: `ModuleNotFoundError: hermes_cli`**
Скопировали код, но не установили пакет. → `uv pip install --python venv/bin/python -e . --no-deps` из каталога `hermes-agent`.

**`install_retention_timer.py` → `owner_runtime_unsafe`**
`uv` создаёт окружение с правами 775, проверка безопасности требует строже. → `chmod -R go-w` на `venv` **и** на `~/.local/share/uv/python`.

**`Unprivileged installer apply failed` при установке секретаря**
Настоящая ошибка скрыта. Чаще всего: (а) сломанный YAML в `config.yaml` — проверьте `python3 -c "import yaml; yaml.safe_load(open('config.yaml'))"`; (б) не установлен системный psycopg — `apt-get install -y python3-psycopg`.

**`owner_unknown` / `owner_required` / `dotenv_unavailable` у manage_passive_secretary.py**
`--owner` — это пользователь Linux (не Telegram ID); запускать от имени этого пользователя; и только питоном из venv профиля (`~/.hermes/hermes-agent/venv/bin/python`), не системным.

## Бот и документы

**Бот пишет «файл готов» / «скачать», а файла нет**
Файл создан на диске, но не доставлен: в ответе не было `MEDIA:<путь>`. → Проверьте, что `SOUL.md` на месте (правило MEDIA в разделе «Документы»), и начните новую сессию: `/new`. Правки SOUL.md действуют только в новой сессии.

**На каждый документ выскакивает «Command Approval Required» с кодом**
В `config.yaml` стоит `approvals.mode: manual`. → Поставьте `smart` (наш дефолт): рутину одобряет автоматика, опасное по-прежнему спрашивает.

**В свойствах документа «generated by python-docx» и дата 2013 года**
Не работает хук очистки. → Проверьте: скрипт установлен (`/usr/local/bin/hermes-clean-docmeta`), в `config.yaml` блок `hooks:` без параметра `matcher`, в `.env` заданы `HERMES_DOC_WORKSPACE` и `HERMES_DOC_AUTHOR`. Перезапустите сервис.

**Напоминания «не работают»**
Проверьте, что в `config.yaml` `cronjob` НЕ находится в `disabled_toolsets` (в нашем шаблоне он включён).

**Голос отвечает не тем голосом / «недостаточно баланса»**
Основной TTS-провайдер без денег — бот тихо переходит на бесплатный edge. → Либо пополните провайдера, либо настройте голос edge в `config.yaml` (`tts.edge.voice`, например `ru-RU-DmitryNeural` — мужской, `ru-RU-SvetlanaNeural` — женский).

## Архив переписки (секретарь)

**Установщик падает на `history_backfill.py` или `legacy_media_seed.py`**
Вы используете ранний коммит `5c893d6` с ошибочным обязательным manifest.
Обновите репозиторий до исправленного release и повторите установку. Не создавайте
пустые файлы-заглушки: эти operator-add-ons не нужны для нового Business-архива.

**Бот подключён в «Telegram для бизнеса», а архив пустой**
Проверьте, что Business-подключение активно, нужный чат не исключён, Telegram
owner совпадает с allowlist профиля, `capture_enabled=true`, PostgreSQL доступен,
а очередь не застряла. После нового сообщения сравните счётчик и время последней
записи в архиве. Наличие дополнительных прав Telegram само по себе сбор не
блокирует.

**В журнале `rights exceed the configured passive capture profile`**
Это ограничение старой версии нашего модуля, не Telegram. Обновите обработчик
Hermes и плагин секретаря вместе до версии с независимым входящим сбором.
Отключение лишних прав в старой версии — временный обход, а не исправление кода.
Обновление не восстанавливает автоматически сообщения, пропущенные ранее.

**«Не вижу переписку за такой-то день», хотя она была**
Ассистент неправильно ищет. Напомните ему (или проверьте, что в SOUL.md есть раздел «Как искать в архиве переписки»): по человеку — сначала `passive_secretary_sources`, затем поиск с широким диапазоном дат; большие периоды — окнами по месяцу.

**`production_requires_empty_test_run` при активации**
В `plugins/passive-secretary/settings.json` осталась метка тестового прогона. → Поставьте `"test_run_id": ""` и повторите активацию.

**Команда `ОТВЕТИТЬ:` не открывает подтверждение**
Проверьте, что модуль активирован с `--enable-outbound-replies`, включены
toolset `passive_secretary_outbound` и `business_reply_enabled`, а в Telegram
Business включены «Ответы на сообщения». Автоматически связанное право «Чтение
сообщений» допустимо; все остальные права должны быть выключены для исходящих
ответов, но их наличие не останавливает сбор архива. Команда должна
находиться в самом начале текущего личного сообщения владельца. Нужен свежий
входящий message anchor не старше 24 часов.

**Нужно отправлять клиентам сообщения по расписанию**
Текущий Telegram Business outbound этого не поддерживает. Внутренние cron-
события намеренно не получают owner permit. Не пытайтесь обходить эту защиту
через архивный текст или автоматическое подтверждение.

## Telegram

**После `/maton` ключ попал в обычный ответ или остался в истории Hermes**
Onboarding plugin не установлен/не включён. Не повторяйте ключ: сначала отзовите
его в Maton → Settings. Затем установите `modules/maton-onboarding/install.py`,
проверьте `plugins.enabled: [maton-onboarding]` и перезапустите gateway.

**`/maton` принял ключ, но сервисы Maton не появились**
Отправьте `/reload-mcp`. Если Maton всё ещё недоступен, проверьте `/maton`:
невалидный ключ не сохраняется, а временная недоступность Maton не включает MCP.

**Maton выдал ссылку, но ассистент говорит, что сервис подключён**
Ссылка означает только `PENDING`. Откройте её, завершите вход и разрешения,
затем попросите Вектор проверить подключение. Готово только при `status=ACTIVE`.

**В логах `Failed to send Telegram message: Chat not found` ровно при перезапуске**
Безобидно: бот пытался отправить прощальное сообщение в момент остановки.

**`FloodWaitError ... ResolveUsernameRequest`** *(для продвинутых сценариев автоматизации)*
Слишком много обращений по @username к Telegram. Подождать (до нескольких часов); в скриптах — использовать ID/кэш вместо повторного резолва имени.

**Бот молчит совсем**
1. Сервис жив? `systemctl status assistant-hermes` (сервер; если агент назвал сервис иначе — спросите его) или процесс `gateway run` запущен (компьютер).
2. В `.env` правильный `TELEGRAM_BOT_TOKEN`?
3. Ваш ID в `TELEGRAM_ALLOWED_USERS`? Бот игнорирует чужих — это защита.
4. Смотрите лог: `journalctl -u assistant-hermes -n 50` — и покажите его агенту.
