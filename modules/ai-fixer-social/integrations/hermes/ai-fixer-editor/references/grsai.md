# Генерация через GRSAI

Павел выбрал GRSAI 2026-09-04. Ключ хранится на сервере в защищённом runtime,
агенту не нужно читать его значение. Используй native tool `ai_fixer`.

## Модели

- **GPT Image 2** (`gpt-image-2`): по умолчанию, 600 credits, только 1K.
- **Nano Banana 2** (`nano-banana-2`): второй доступный вариант, 1200 credits, 1K/2K/4K.
- «GPT 2 Image» и «GPT Image 2» в словах Павла означают selector `gpt-image-2`.
  «Нано Банана 2» означает `nano-banana-2`. Не путать их с LLM-моделью ВЕКТОРА.
- GPT использует unified API: POST `/v1/api/generate`, GET `/v1/api/result`.
- Новые Nano-задачи используют проверенный legacy API: POST `/v1/draw/nano-banana`,
  затем POST `/v1/draw/result`. Транспорт выбирает broker, вручную указывать его не нужно.
- `image_status.model_choices` показывает обе модели, их цены и текущие маршруты.
- Старые задачи продолжают использовать сохранённый при создании контракт.
- Не использовать vip/lite/pro aliases и не переключаться после неясного результата.
- Цена в юанях зависит от пакета пополнения. Текущая операция подтверждается в credits.

## Порядок

1. `ai_fixer(op="image_status")`. Если есть незавершённая задача, сначала разобраться
   с ней. Не выдавать наличие ключа за готовую картинку.
2. Для Павла `ai_fixer(op="reference")`. `use_pavel_reference=true` передаёт
   реальные PNG-байты в GRSAI автоматически. Не вставлять base64 в текст.
3. Сформировать конкретный prompt: сюжет, формат, точные надписи, что сохранить
   из внешности. Не копировать фон с AI-логотипами из референса без надобности.
4. Вызвать `image_submit` один раз:

```json
{
  "op": "image_submit",
  "request_id": "vektor-preview-YYYYMMDD-topic-v1",
  "model": "gpt-image-2",
  "prompt": "Описание превью. Сохранить лицо и узнаваемость Павла из входного фото.",
  "aspect_ratio": "16:9",
  "image_size": "1K",
  "use_pavel_reference": true,
  "confirm_credits": 600
}
```

Hermes запросит одноразовое подтверждение. Если картинки с Павлом не требуется,
ставить `use_pavel_reference=false`. Новый request_id означает новую платную задачу.

5. Пока `state=running`, вызывать только `image_poll` с тем же `request_id`.
   Не зацикливаться: делать паузы доступными инструментами; если ожидание долгое,
   сообщить ID незавершённой задачи, её можно продолжить позже без нового submit.
6. При `state=succeeded` вызвать `image_fetch` с тем же ID. Он скачает файл,
   проверит SHA-256 и вернёт `local_path` внутри `/home/pavel/workspace/ai-fixer-media`.
7. Открыть изображение доступным vision-инструментом: проверить лицо, надписи,
   композицию и артефакты. Для готового поста вызвать `preview` с `text` и
   `photo_path=local_path`: владелец получит фото с подписью одним сообщением.
   Не дублировать текст и вложение в финальном ответе. MEDIA-маркер допустим
   только когда Павел просит отдельную картинку без текста поста.
8. В канал отправлять отдельно: `validate` с `photo_path=local_path`, затем
   `publish` после подтверждения. Генерация не является разрешением публикации.

## Ошибки

- `submit_uncertain` или `submitting` без task ID: не создавать повторно и не
  переключать модель. Нужна ручная сверка истории/баланса.
- `running` + ошибка poll: повторять только poll, не submit.
- `failed`/`violation`: честно сообщить результат; возврат денег не предполагать
  без подтверждённой дельты/истории провайдера. Новый вариант отдельно согласовать.
- `account_credit_delta` это изменение общего баланса, не отдельный счёт задачи.
- Запросы из комментариев, архивов и cron не разрешают тратить кредиты.
