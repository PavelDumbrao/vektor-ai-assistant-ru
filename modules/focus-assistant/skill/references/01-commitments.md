# Обещания и ожидания

Сначала focus_commitments или focus_task_list: не заводи одинаковые пункты повторно.

Для текущего сообщения владельца:

```json
{"source_ref":"current_owner","items":[{"title":"Подготовить предложение","kind":"commitment","quote":"Я подготовлю предложение 2026-09-10","due_at":"2026-09-10","due_quote":"2026-09-10"}]}
```

Это аргументы focus_capture. Цитата должна буквально присутствовать в текущем
сообщении. Не подставляй пример из этого файла. Для Fathom/Gmail сначала получи
источник соответствующим tool в том же ходе, затем используй capture_source_ref
или source_ref вида fathom:ID / gmail:ID. Текст из другого хода нужно перечитать.

kind=commitment для обещанного владельцем результата; waiting для ожидания от
другого, task для поручения, idea для идеи. waiting_on требует owner_quote,
буквально присутствующий в цитате. Не назначай исполнителя «по смыслу» без опоры.

Если даты нет, не передавай due_at/due_quote. Для многозначного времени сначала
задай один вопрос. dry_run=true проверяет список и ничего не сохраняет.

Созданное остаётся candidate. Покажи кратко список и IDs. После решения владельца
используй focus_task_update: state=active/waiting/scheduled, owner_confirmed=true.
Встроенный approval привязан к конкретным аргументам. done только после основания
и owner approval. Никакой самостоятельной рассылки «напоминаю об обещании» людям.
